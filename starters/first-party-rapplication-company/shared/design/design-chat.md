# Design understandable chat and recovery journeys

Room `design` (Conversation and interaction design). Blocked until [[specify-product]] is done.

Define empty, add, list, completion, duplicate, refusal and restart behavior. Specify host keyboard and announcement checks without claiming they were observed. Keep every action inside the product scope.

## Inputs

- `deliverables/product-spec.md`, from [[specify-product]]
- `docs/chat-acceptance.md`: [[chat-acceptance]]
- `docs/craftsmanship-rubric.md`: [[craftsmanship-rubric]]

## Outputs

## Acceptance

- Each journey has expected output, failure behavior and a verification method.
- Reference process memory is never presented as durable storage.
- Unobserved host accessibility is labeled not observed.
